# Проект: Персональный AI-тренер (Telegram) с приоритетом пляжного волейбола

## Цель
Автономный помощник, ведущий спортивную подготовку с ПРИОРИТЕТОМ развития в
пляжном волейболе. Зал, питание и восстановление — подчинённые системы,
обслуживающие волейбол. Всё общение — в Telegram; правки текстом автоматически
пересчитывают план.

## Стек (выбран, бесплатный)
- Backbone: Python (aiogram или python-telegram-bot), Docker на VPS.
- LLM «мозг»: Google Gemini API (free tier). ОБЯЗАТЕЛЬНО абстрагировать за
  интерфейсом `LLMClient` (метод `complete(system, messages) -> str`), чтобы
  переключение на Anthropic/OpenAI было одной строкой конфига.
- Хранилище: SQLite (единый источник правды) + версионирование плана.
- Планировщик: APScheduler (утренние пуши, воскресный ревью).
- Секреты: .env, НЕ коммитить, НЕ логировать (см. правило secrets-local-only).

## Единый источник правды (STATE)
- profile: атлет (intake-данные), цели, травмы, доступ к залу/оборудованию.
- week_plan: структурированный план недели (сессии волейбол/зал/восстановление —
  время, тип, длительность, нагрузка). Версионируется при каждой правке.
- logs: daily check-in (RPE, крепатура, сон, настроение), лог питания, факт
  выполнения. Все модули ЧИТАЮТ STATE; обработчик Телеграма его МУТИРУЕТ.

## Модули (композиция, каждый делает одно)
1. profile        — intake и поддержка данных атлета.
2. schedule-sync  — календарь недели; типы волейбола (техническая/игровая/
                    групповая); отмены/переносы; турнирный календарь и пикинг.
3. volleyball-dev — приоритет: прыжок, ловкость, контроль мяча, периодизация
                    под турниры.
4. gym-plan       — ДОПОЛНЯЮЩАЯ сила/мощность, авторегуляция вокруг волейбольной
                    нагрузки.
5. nutrition      — цели по калориям/макросам под нагрузку; лог (текст/фото);
                    оптимизация; ТОЛЬКО доказательные добавки.
6. recovery       — восстановление + prehab плеча/колена/голеностопа + мобильность.
7. weekly-adapt   — раз в неделю: собрать фидбэк, пересчитать планы, объяснить
                    изменения человеческим языком.

## Жёсткие правила (инварианты)
- ПРИОРИТЕТ: зал НИКОГДА не вредит волейболу. Нет тяжёлых ног за 48ч до
  игры/турнира; объём зала автоснижается в тяжёлые волейбольные недели.
- Правка из Телеграма → сначала ПОДТВЕРЖДЕНИЕ намерения («Понял так: … Применяю?»),
  только потом мутация плана и пересчёт зависимых модулей.
- Питание/добавки — не медицина. Дисклеймер + «при травме/симптомах — к врачу».
- Автопрегуляция: плохой daily check-in (усталость/сон) → сегодняшняя нагрузка
  автоматически снижается, с объяснением.

## Основные потоки
- Утренний пуш: план на день + быстрый daily check-in.
- Приём правки: перенос/отмена сессии, изменение длительности/типа, замена
  питания → подтверждение → пересчёт → новый план.
- Воскресный ревью (weekly-adapt): итоги недели → адаптация на следующую.
- Периодически: обоснованные предложения по восстановлению/мобильности/добавкам.

## Порядок сборки
- Фаза 0: intake (profile) — вопросы атлету, затем схема БД и структура проекта
  ДО кода.
- MVP: Telegram-эхо + профиль + недельный план + утренний пуш.
- Дальше модули итеративно: schedule-sync → gym-plan/volleyball-dev → nutrition
  → recovery → weekly-adapt.

## Деплой
Docker на VPS. После изменений .py — `up --build`, не просто `restart`
(см. правило docker-deploy).

## schedule-sync: модель взаимодействия (утилита утреннего пуша) — УТВЕРЖДЕНО

Утренний пуш 08:00 (Самара, UTC+4) показывает сессии дня + быстрый check-in.
У сессии дня 4 исхода; частый случай («всё по плану») = 1 тап.

Клавиатура:
- [✅ Всё по плану] — подтверждает все сессии дня одним тапом.
- [✏️ Изменить: <сессия>] на каждую сессию → под-меню:
  - [✅ Состоится]
  - [🌧 Отменить сегодня]
  - [🕐 Другое время сегодня] → FSM спрашивает время (текст/быстрые слоты)
  - [📅 Перенести на день] → [Пн..Вс] → время («уточню позже» = tentative)
- Check-in: [😀 Свежий] [😐 Норм] [😩 Устал] → влияет на автопрегуляцию дня.
- Свободный текст работает всегда (отмена/перенос/добавление сессии).

Обработка правки: parse → ПОДТВЕРЖДЕНИЕ («Понял так: … Применяю?») → мутация
sessions → пересчёт НЕДЕЛИ (не только дня) → показать обновление.

Реакция на события:
- Отмена (дождь): освобождается окно → мягко предложить лёгкий зал/мобильность/
  отдых; снятая волейбольная нагрузка разрешает чуть тяжелее следующий зал.
- Перенос по времени (сегодня): правит time; проверить коллизию с залом дня.
- Перенос на другой день: пересчёт недели; если два тяжёлых дня подряд или
  тяжёлые ноги <48ч до игры — ПРЕДУПРЕДИТЬ и предложить подвинуть зал.
- Добавление сессии: проверка коллизий + автопрегуляция объёма зала вниз.

ПРАВИЛО КОЛЛИЗИИ (инвариант): при конфликте волейбол+зал в один день зал ВСЕГДА
уступает волейболу — двигается на свободный день или превращается в лёгкий/
мобильность. Бот показывает, что сделал, с возможностью отменить (undo).

Каждое изменение пишется в events (план vs факт) → кормит weekly-adapt.
